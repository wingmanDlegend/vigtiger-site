# 대범한사람들(VIGTIGER) 홈페이지

Next.js(App Router) 기반 회사 홈페이지입니다. GitHub에 푸시하면 Vercel이 자동으로 배포합니다.

## 페이지

한국어는 접두사 없이, 영어는 `/en` 을 붙입니다. (예: `/services/to` ↔ `/en/services/to`)

| 주소 | 내용 |
| --- | --- |
| `/` | 홈 |
| `/about` | 회사소개 |
| `/services/advirtual` | 애드버추얼 |
| `/services/shopping` | 쇼핑올인원 |
| `/services/to` | 티오(TO) |
| `/apply/creator` | 크리에이터 비즈니스 상담 신청 |
| `/apply/advertiser` | 광고주 광고 신청 |
| `/apply/partner` | 상품 파트너 입점 신청 |
| `/privacy` | 개인정보처리방침 |
| `/insights` | 인사이트 첫 화면 — 업계 동향·Hot Contents 최신 글 (한국어 전용) |
| `/insights/trends`, `/insights/trends/YYYY-MM-DD` | 업계 동향 — 데일리 인플루언서 마케팅 기사 정리 |
| `/insights/hot`, `/insights/hot/YYYY-MM-DD` | Hot Contents — 전날 화제가 된 소셜 콘텐츠 추천 |
| `POST /api/apply` | 신청서 접수 → Supabase 저장 |

신청서 주소에 `?interest=to` 처럼 붙이면 관심 서비스가 미리 체크됩니다 (`advirtual`, `shopping`, `to`).
기존 vigtiger.com(Notion) 페이지 주소는 `next.config.ts` 에서 새 페이지로 영구 리디렉션됩니다.

## 자주 고치는 곳

- **홈·공통 문구(한/영)**: `lib/dictionary.ts`
- **서브 페이지 문구(한/영)**: `lib/pages.ts`
- **신청서 항목·선택지**: `lib/forms.ts` (화면과 서버 검증이 같은 정의를 씁니다)
- **색·글꼴·레이아웃**: `app/globals.css` (포인트 색은 `--accent`, 기본 글꼴은 Apple SD Gothic Neo, 대체 글꼴 Noto Sans KR)

## 도메인 역할

| 도메인 | 역할 | 코드 |
| --- | --- | --- |
| www.vigtiger.com | 대범한사람들 홈페이지 | `app/[lang]` |
| partners.vigtiger.com | 브랜드 비즈니스 파트너 (티오 제품 등록·수정 요청) | `app/partners` |
| admin.vigtiger.com | 대범한사람들 업무 관리 시스템 | `app/admin` |
| to.vigtiger.com | 크리에이터용 티오(TO) — 서비스 소개 · 제품 리스트 · 상담신청 · 회사소개 | `app/tosite` |

한 프로젝트를 `proxy.ts`가 도메인별로 나눠 보여 줍니다 (주소창은 그대로, 내부 경로만 `/admin/…`, `/partners/…`). 예전 주소 `vigtiger.com/admin/…`, `vigtiger.com/partners/…`, `vigtiger.com/tosite/…` 는 각 전용 도메인으로 이동합니다. 로컬에서는 `admin.localhost:3000`, `partners.localhost:3000`, `to.localhost:3000` 으로 확인합니다.

## 업무 관리 시스템 (admin.vigtiger.com)

로그인: 직원 계정(이메일·비밀번호, 대표 관리자가 [설정 › 직원 계정]에서 발급) 또는 **대표 관리자 비밀번호**(`ADMIN_PASSWORD`). 검색엔진에는 노출되지 않습니다.

- 유형별 탭(크리에이터·광고주·상품 파트너·TO 신청)과 건수, 상태 필터, 이름·회사·이메일·연락처·관심 제품 검색
- 목록에서 바로 처리 상태 변경: 신규 → 검토 중 → 연락함 → 진행 확정 / 보류·종료
- 상세 화면: 신청 내용 전체(선택지는 한글 라벨로 표시), 내부 메모 저장, 신청 삭제(2단계 확인 후 영구 삭제 — 테스트·중복·스팸 정리용)
- 엑셀(CSV) 내려받기: 현재 보고 있는 탭·필터 그대로. 유형 탭에서 받으면 항목별로 칸이 나뉩니다.

### 관리자 메뉴 구조

왼쪽 사이드바(휴대폰에서는 위쪽 가로 메뉴), 로그인하면 **홈**부터 열립니다. 메뉴 옆 숫자는 처리할 일(신규 신청·정산 대기·검토 대기 초안)입니다.

| 그룹 | 메뉴 | 화면 (admin.vigtiger.com) |
| --- | --- | --- |
| 홈 | 홈 | `/` 전체 업무 현황 |
| 비즈니스 | 제휴 신청 | 현황 `/dashboard/applications` · 목록 `/applications` |
| 비즈니스 | 공동구매 | 현황 `/dashboard/groupbuys` · 목록 `/groupbuys` |
| 티오 파트너스 | 현황 · 승인 대기 · 제품 · 브랜드·계정 · 제품 리스트 · 추천·핫딜 | `/to` · `/to/review` · `/to/products` · `/to/brands` · `/to/catalog` · `/to/promo` |
| 콘텐츠 | 업계 동향 · 핫 콘텐츠 | `/insights?kind=trends` · `/insights?kind=hot` |
| 설정 | 직원 계정 · 작업 기록 | `/settings/accounts` · `/settings/log` |

모든 화면 머리는 '그룹 → 제목(+도구) → 설명 → 탭(현황 · 목록)' 순서입니다. 메뉴 정의는 `lib/admin/nav.ts`.

### 대시보드

- **통합** `/`: 오늘 확인할 일(신규 신청·정산 대기·오늘 인사이트 상태), 이번 달 vs 지난달 핵심 숫자, 월별 신청 수·공동구매 매출, 최근 신청·공동구매.
- **신청 접수** `/dashboard/applications`: 기간(최근 30일·90일·올해·전체)별 유형·처리 단계·확정률, 월별 추이(유형 누적), 크리에이터 관심 서비스·구독자·카테고리·관심 제품, 광고주 예산·제품 카테고리.
- **공동구매** `/dashboard/groupbuys`: 기간별 매출·회사 수익·건당 평균·전환율·정산 대기, 월별 매출·수익, 브랜드·크리에이터·플랫폼·제품 순위, 재진행 판단·진행 상태·정산 비율. 시작일 기준, 취소 건 제외.
- 모든 차트는 서버에서 그리는 가벼운 SVG/HTML(애니메이션 없음)이고, 막대에 마우스를 올리면 값이, '표로 보기'를 누르면 숫자 표가 나옵니다.

### 공동구매 결과 (`/groupbuys`)

- 공동구매 한 건마다 기본 정보(브랜드·제품·크리에이터·플랫폼·기간·상태), 판매 실적(정가·공구가·판매 수량·총 매출), 수익 정산(크리에이터 수수료율·정산액·회사 수익·정산 완료·정산일), 콘텐츠 성과(링크·조회수·클릭 수), 재진행 판단(추천/보류/안 함·이유), 메모를 기록합니다.
- 총 매출을 비우면 공구가 × 판매 수량, 크리에이터 정산액을 비우면 총 매출 × 수수료율로 저장합니다. 할인율·전환율(판매÷클릭)은 화면에서 계산해 보여 줍니다.
- 목록 위에 건수·총 매출·판매 수량·정산액·회사 수익·정산 대기 합계(취소 제외), 아래에 브랜드·크리에이터별 매출 TOP 5가 나옵니다. 상태·연도·검색·정산 대기 필터, CSV 내려받기 지원.
- **엑셀 업로드**: `/groupbuys/import` 에서 .xlsx 또는 CSV를 올리면 머리글을 자동 인식(예: 매출액→총 매출, 수수료율→크리에이터 수수료율)하고 줄별 오류를 미리 보여 줍니다. 한 줄이라도 오류가 있으면 저장하지 않습니다. 양식은 `/groupbuys/template`.
- 데이터는 Supabase `groupbuys` 테이블에 있고, 공개 키로는 읽을 수 없습니다(서버의 secret 키로만 접근).

새 신청이 저장되면 `SLACK_WEBHOOK_URL` 로 지정한 슬랙 채널에 알림이 가고, 알림의 버튼으로 해당 신청의 관리자 화면을 바로 열 수 있습니다. 알림이 실패해도 접수는 정상 저장됩니다.

데이터는 Supabase 프로젝트 `vigtiger-site` 의 `applications` 테이블에 있습니다.
테이블은 RLS로 "등록만" 허용되어 있어 공개 키로는 읽을 수 없고, 관리자 페이지는 서버에서 비밀 키로만 조회합니다.

## 인사이트 (업계 동향 · Hot Contents)

- 평일 아침 예약 작업 두 개가 초안을 Supabase `insight_posts` 테이블에 넣습니다 (`status = draft`). `kind` 가 `trends`(업계 동향: 기사 정리) 또는 `hot`(Hot Contents: 전날 화제 콘텐츠)이고, 같은 날짜에 종류별로 1건씩입니다.
- Hot Contents 항목에는 플랫폼·채널·확인된 반응 수치·왜 떴나·활용 포인트·관련 기사 링크가 들어갑니다. 원본 게시물은 링크로만 연결하고 썸네일·영상은 옮기지 않습니다.
- 관리자 페이지 `/insights` 에서 제목·도입·기사 요약·'대범한사람들의 시선'을 고치고, 기사를 빼거나 순서를 바꾼 뒤 **저장하고 게시**를 누르면 `/insights` 에 올라갑니다. 게시 취소·삭제도 같은 화면에서 합니다.
- 평일 오전 9시 30분에 예약 작업이 그날 아직 게시되지 않은 초안을 자동 게시합니다. 그 전에 관리자 페이지에서 고치거나 게시 취소·삭제할 수 있습니다.
- 한국어 홈의 **Today's Issue** 섹션은 업계 동향·Hot Contents의 가장 최근 게시 글을 보여 줍니다(5분 캐시, 관리자 게시 시 즉시 갱신).
- 공개 키로는 게시된 글만 읽을 수 있습니다(RLS). 홈페이지는 5분마다, 게시 버튼을 누르면 즉시 새로 고칩니다.
- 요약은 원문을 옮기지 않고 2~3문장으로 새로 쓰고, 원문 링크와 언론사를 꼭 남깁니다.

## TO 파트너스 (partners.vigtiger.com — 티오 제품 관리)

브랜드 담당자 전용 사이트입니다. 승인·브랜드·계정 관리는 admin.vigtiger.com [티오 파트너스] 메뉴에서 합니다. 관리자 계정은 파트너 사이트에, 브랜드 계정은 관리 사이트에 로그인할 수 없습니다.

- **브랜드 담당자 계정**: 관리자가 브랜드 화면에서 발급 → 임시 비밀번호(한 번만 표시) → 첫 로그인 때 새 비밀번호로 변경. 5번 틀리면 15분 잠금
- **승인 흐름**: 담당자의 새 제품·수정·삭제·브랜드 정보 변경은 모두 '승인 대기'로 들어가고, 관리자가 승인해야 반영. 새 제품은 승인 때 일련번호(브랜드코드-다음 번호) 자동 부여. 관리자가 직접 고치면 바로 반영
- **제품 관리** (파트너 메뉴 `/my`): 등록 `/my/new` · 정보 수정 `/my/<id>` · 삭제 — 모두 관리자 승인 후 반영. 제품마다 **TO 노출** 스위치(승인 없이 바로 반영, 끄면 to.vigtiger.com·제품 리스트·인쇄에서 빠짐)
- **브랜드 TO 노출 신청** (파트너 [브랜드 정보]): 지금 노출 중이면 '노출 중지 신청', 아니면 '노출 신청' → admin [승인 대기]에서 처리(또는 브랜드 화면에서 '리스트에 노출'을 직접 바꾸면 신청도 함께 처리). 브랜드 이름·영문 이름·코드는 다른 브랜드와 겹치면 저장되지 않음
- **추천·핫딜 신청** (파트너 메뉴 `/promo`): 게시 중 제품을 이번 주 추천 또는 핫딜로 신청(희망 기간·핫딜 문구·전달 내용) → admin [추천·핫딜] 맨 위 '브랜드 신청'에서 올리기/반려. 핫딜은 신청한 문구·마감일이 그대로 들어감 (`to_promo_requests`)
- 브랜드의 모든 신청(제품 등록·수정·삭제, 브랜드 정보, 노출, 추천·핫딜)은 슬랙 알림 + 메뉴 배지 + 관리 홈 '오늘 확인할 일'에 함께 잡힘
- **가격·판매 조건**: 정가 · 온라인 판매가 · 공구가 · 판매 수수료(%) · 자사몰 공구 진행(진행/안 함/협의) · 사은품 · 기타 사항 — 브랜드와 관리자만 보고 크리에이터용 화면에는 나오지 않음. 수정은 다른 항목처럼 승인 후 반영
- **제품 리스트**: 관리 `/to/catalog`(분류·브랜드·협찬/대여·검색), 파트너 `/catalog`(자기 브랜드) — 게시 중 제품을 카드로 보여 주는 게 기본, `인쇄/PDF로 보기`(`…/print`, 같은 조건)에서 게시 중 제품으로 PDF와 같은 모양의 리스트를 만들고, 브라우저 인쇄로 A4 PDF 저장
- **초기 데이터**: `data/partners-seed.json` (2025-11-05 판 TO 제품 리스트 PDF에서 추출, 브랜드 92 · 제품 374) + 이미지 `public/partners-seed/`. 브랜드 표가 비어 있을 때 관리 사이트 [티오 파트너스] 첫 접속 시 한 번 자동 입력
- **DB**: `partner_brands`, `partner_users`(scrypt 해시), `to_products`, `partner_events`(작업 기록) — 모두 RLS 켜짐·정책 없음(서버 전용). 새 이미지는 Supabase Storage `partners` 버킷
- 새 요청이 들어오면 슬랙(SLACK_WEBHOOK_URL)으로 알림

## 홈페이지 ↔ 티오·파트너스 연결

- 모든 홈페이지 화면 맨 위 '패밀리 사이트' 띠: 티오 제품 리스트 · 브랜드 파트너스 (`components/Family.tsx`)
- 홈: '크리에이터라면 → 티오 / 브랜드라면 → 파트너스' 두 갈래 카드 (티오 쪽은 제품 미리보기 4개 — 이번 주 추천 → 핫딜 순, 둘 다 없으면 방문할 때마다 서로 다른 분류에서 무작위)
- TO 서비스 페이지: 첫 버튼이 to.vigtiger.com 제품 리스트·상담신청, 브랜드용 파트너스 로그인 링크
- 협업 문의 영역·바닥글·신청서(크리에이터·상품 파트너) 위 안내에도 바로가기
- 클릭은 GA4 `family_site_click` 이벤트(site · placement · path)로 남아 어디서 넘어가는지 볼 수 있어요. 같은 창에서 이동

## 티오 크리에이터 사이트 (to.vigtiger.com)

크리에이터가 티오 제품을 보고 바로 신청하는 공개 사이트입니다. 메뉴: TO 서비스 소개 `/` · TO 제품 리스트 `/products` · 상담신청 `/apply` · 회사소개 `/about`.

- **제품 리스트**: 이번 주 추천 → 핫딜 → 전체 제품(분류 탭 + 검색, 분류 → 브랜드 → 제품 순). 게시 중(승인) 제품과 사용 중인 브랜드만 보이고, 내용은 TO 파트너스 데이터를 그대로 씁니다.
- **이번 주 추천 · 핫딜 노출**: admin [티오 파트너스 › 추천·핫딜] `/to/promo`에서 제품을 찾아 올리기·내리기·순서 바꾸기, 핫딜은 카드 문구와 마감일(다음 날부터 자동으로 빠짐), '모두 내리기'. 비어 있으면 사이트에서 그 묶음이 숨겨집니다. (`to_products.pick_week/pick_sort/hot_deal/hot_sort/hot_note/hot_until`)
- **찜하기**: 제품 카드의 ♡로 찜(로그인 없이 그 브라우저에 저장, `components/tosite/wish.ts`). 찜이 있으면 화면 아래 '찜한 제품 N로 상담신청' 바로가기가 떠요.
- **상담신청**: 이름·연락처·채널 정보 + **써보고 싶은 브랜드·제품 1곳 필수, 최대 2곳** + 콘텐츠 형태. 고르는 방법은 ① 찜한 제품에서 1~2개 체크 ② 드롭다운으로 직접 고르기, 두 가지. 같은 브랜드를 두 번 고르려면 서로 다른 제품이어야 해요. 제품 카드의 '신청하기'로 들어오면 그 제품이 찜되고 첫 번째로 골라져 있습니다. 서버에서 게시 중인 브랜드·제품인지 다시 확인한 뒤 `applications`(type `to`)에 저장 → admin [제휴 신청]의 'TO 신청' 탭에서 다른 신청과 함께 처리 · CSV · 슬랙 알림.
- 데이터는 5분 캐시, 관리자 화면에서 제품·브랜드·추천·핫딜을 바꾸면 즉시 갱신(`revalidateTag("to-site")`).

## 환경변수 (Vercel 프로젝트 설정)

| 이름 | 값 | 용도 |
| --- | --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL | 공통 |
| `SUPABASE_PUBLISHABLE_KEY` | Supabase publishable(공개) 키 | 신청서 등록 |
| `SUPABASE_SECRET_KEY` | Supabase secret 키 (`sb_secret_…`), **Sensitive** 로 저장 | 관리자 페이지 조회·수정 |
| `ADMIN_PASSWORD` | 관리자 페이지 비밀번호, **Sensitive** 로 저장 | 관리자 로그인 |
| `SLACK_WEBHOOK_URL` | (선택) 슬랙 Incoming Webhook 주소, **Sensitive** 로 저장 | 새 신청 슬랙 알림 |
| `NEXT_PUBLIC_GA_ID` | (선택) GA4 측정 ID. 비우면 코드 기본값 `G-17F4EG2VG3`(Google 태그 ID) 사용 | 방문 분석 |
| `NEXT_PUBLIC_SITE_URL` | (선택) 대표 주소. 기본값 `https://vigtiger.com` | SEO |

비밀번호나 secret 키를 바꾸면 기존 관리자 로그인은 모두 풀립니다.

## 방문 분석 (Google Analytics 4)

공개 페이지(한/영)에 Google 태그 `G-17F4EG2VG3` 이 실립니다(`components/Analytics.tsx`). 데이터는 GA4 속성 `G-17F4EG2VG3` 에 쌓입니다. 측정 ID가 아닌 **태그 ID**를 넣어야 하며, 대상 ID만 넣으면 스크립트가 404로 실패합니다. 다른 속성으로 바꾸려면 `NEXT_PUBLIC_GA_ID` 를 설정하고 다시 배포하세요. 관리자 페이지에는 싣지 않습니다.

- 페이지 이동은 GA4 '향상된 측정'의 브라우저 기록 기반 페이지 변경으로 자동 집계됩니다.
- 신청서 접수에 성공하면 `generate_lead` 이벤트를 보냅니다 (매개변수 `form_type`: creator·advertiser·partner, `form_lang`: ko·en). 이름·연락처 등 개인정보는 보내지 않습니다.
- 개인정보처리방침 6조에 쿠키·행태정보 수집과 거부 방법을 적어 두었습니다.

Vercel 프로젝트 → Settings → Domains 에서 `vigtiger.com`, `www.vigtiger.com` 을 추가하고 안내되는 DNS 레코드를 도메인 관리 업체에 등록하면 됩니다. 연결 후 `NEXT_PUBLIC_SITE_URL` 도 설정하세요.

### 계정 권한

| 계정 | 로그인하는 곳 | 만드는 사람 | 할 수 있는 일 |
| --- | --- | --- | --- |
| 대표 관리자 | admin (관리자 비밀번호) | — (환경변수 `ADMIN_PASSWORD`) | 전부 + 직원 계정 발급·재발급·중지·삭제 |
| 직원 계정 | admin | 대표 관리자 ([설정 › 직원 계정]) | 업무 관리 전부 + 브랜드 담당자 계정 관리. 직원 계정 관리는 불가, 내 비밀번호 변경만 |
| 브랜드 담당자 | partners | 대표 관리자·직원 (브랜드 화면) | 자기 브랜드 제품 등록·수정·삭제 요청, 브랜드 정보 수정 요청 |

이메일은 직원·브랜드 계정 전체에서 하나만 쓸 수 있고, 직원 계정은 partners에, 브랜드 계정은 admin에 로그인할 수 없습니다.
